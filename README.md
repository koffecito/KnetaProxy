# KnetaProxy

KnetaProxy — автоматизированный инструмент для разбора и технической проверки конфигураций, формирования подписок и отправки сводного отчёта в Telegram.

> Проект не предоставляет VPN-серверы или доступ к ним. Используйте только источники и конфигурации, которые вы вправе использовать.

## Возможности

- загружает источники подписок из GitHub Secret `SUBSCRIPTIONS`;
- поддерживает конфигурации `vless://`, `vmess://`, `trojan://`, `hysteria2://` и `hy2://`;
- разбирает конфигурации и удаляет дубликаты;
- выполняет проверки через Cheburcheck и Xray;
- поддерживает режим дополнительной проверки `generate_204`, `tcp` или `no`;
- определяет внешний IP и страну после успешного подключения;
- формирует основную подписку максимум из 100 конфигураций и полную подписку из всех прошедших проверку;
- сохраняет отчёт и историю результатов;
- может отправлять статистику в Telegram;
- запускается по расписанию через GitHub Actions.

## Как работает проверка

1. Скрипт читает строки из секрета `SUBSCRIPTIONS`.
2. Строки `http://` и `https://` загружаются как источники подписок; поддерживаемые прямые конфигурации можно указывать отдельными строками.
3. Конфигурации разбираются, проверяются и очищаются от дубликатов.
4. Для проверки соединения используется Xray. Проверка IP выполняется через Cheburcheck.
5. После успешного соединения определяется внешний IP и, если возможно, страна.
6. Результаты сохраняются в `proxies/`, а Telegram-уведомление отправляется при наличии нужных секретов.

## Настройка источников — GitHub Secret

1. Откройте репозиторий на GitHub.
2. Перейдите в **Settings → Secrets and variables → Actions**.
3. Нажмите **New repository secret**.
4. В поле **Name** укажите `SUBSCRIPTIONS`.
5. В поле **Secret** вставьте URL источников — по одному на строку. Можно также указывать поддерживаемые прямые конфигурации отдельными строками.
6. Сохраните секрет.

Пример содержимого секрета (используйте свои реальные URL; этот пример не является рабочим источником):

```text
https://example.com/subscription-1
https://example.com/subscription-2
```

Не добавляйте реальные источники, токены или конфигурации в README, issues или обычные файлы репозитория. Скрипт намеренно не выводит содержимое строк источников в логи.

## Настройка режима проверки

В `type.txt` укажите ровно один режим:

```text
generate_204
```

- `generate_204` — дополнительная HTTP-проверка;
- `tcp` — дополнительная TCP-проверка;
- `no` — дополнительная проверка отключена.

## Результаты

В каталоге `proxies/` сохраняются:

| Файл | Назначение |
|---|---|
| `working.txt` | Основная подписка, не более 100 конфигураций |
| `all.txt` | Все конфигурации, прошедшие проверки |
| `report.txt` | Итоги запуска, статистика и ошибки |
| `history.json` | История предыдущих запусков |

Telegram-статистика по странам и протоколам относится к основной подписке `working.txt`, а не ко всему набору найденных конфигураций. Результаты отражают состояние на момент запуска и не гарантируют дальнейшую доступность серверов.

## GitHub Actions

Workflow: `.github/workflows/check-proxies.yml`.

Он запускается автоматически в **04:00 и 16:00 UTC** и может быть запущен вручную через **Actions → Check proxies → Run workflow**. Workflow устанавливает Python и Xray, проверяет настройки, запускает `checker.py`, отправляет Telegram-отчёт при наличии токена и сохраняет обновлённые результаты в репозитории.

Для работы необходимо создать секрет `SUBSCRIPTIONS`. Без него проверка завершится с понятной ошибкой.

## Настройка Telegram

Для отправки уведомлений создайте секрет репозитория `TELEGRAM_BOT_TOKEN` и добавьте ID чатов в `telegram_chats.txt` — по одному ID на строку. Файл с ID чатов не должен содержать токены или пароли.

Если секрет `TELEGRAM_BOT_TOKEN` не задан, шаг отправки уведомления пропускается. Не публикуйте токен бота: любой, кто получит его, может управлять ботом в пределах доступных ему возможностей.

## Локальный запуск

Требуются Python 3.11+, зависимости из `requirements.txt` и установленный Xray. Установите зависимости:

```bash
pip install -r requirements.txt
xray version
```

Перед запуском задайте переменную окружения `SUBSCRIPTIONS` с многострочным содержимым секрета. Например, в Linux/macOS можно загрузить её из защищённого локального файла, который не добавляется в Git, либо задать в окружении терминала. Не передавайте секрет прямо в командной строке, если она может сохраняться в истории оболочки.

Затем выполните:

```bash
python validate.py
python checker.py
python telegram_notify.py
```

`telegram_notify.py` отправит сообщение только при наличии `TELEGRAM_BOT_TOKEN` и настроенных чатов.

## Возможные причины отсутствия конфигурации в результате

Конфигурация может не попасть в итоговый файл, если она имеет неверный формат, является дубликатом, не проходит проверку IP, не устанавливает соединение через Xray или не проходит выбранную дополнительную проверку. Ошибки и сводка записываются в `proxies/report.txt`.

## Безопасность и ответственность

- Не храните URL источников, приватные конфигурации, пароли и токены в открытых файлах репозитория.
- GitHub Secrets скрывает значение секрета в настройках и предоставляет его workflow, но не защищает от намеренного вывода значения самим кодом. Поэтому не добавляйте отладочные команды, которые печатают секрет.
- Проверяйте происхождение источников и соблюдайте применимые законы и условия сторонних сервисов.
- Проверка соединения не гарантирует постоянную доступность, безопасность или правомерность использования стороннего ресурса.

Проект предназначен для изучения программирования, парсинга данных, сетевой диагностики и автоматизации. Этот раздел не является юридической консультацией.
