# KnetaProxy

Автоматизированный инструмент для сбора, разбора и технической проверки конфигураций прокси с последующим формированием готовых подписок.

> Проект не является VPN-сервисом и не предоставляет серверы. Он предназначен для изучения программирования, сетевых проверок, парсинга конфигураций, Xray, GitHub Actions и API.

## Возможности

KnetaProxy:

- загружает конфигурации из `subscriptions.txt`;
- поддерживает `vless://`, `vmess://`, `trojan://`, `hysteria2://` и `hy2://`;
- удаляет дубликаты и некорректные строки;
- проверяет IP серверов через Cheburcheck;
- проверяет фактическое соединение через Xray;
- поддерживает режимы дополнительной проверки `generate_204`, `tcp` и `no`;
- определяет внешний IP после подключения и его страну;
- формирует основную подписку до 100 конфигураций;
- формирует TOP-10;
- формирует полный список всех прошедших проверку конфигураций;
- сохраняет статистику и историю стабильности;
- при настройке Telegram отправляет отчёт;
- может автоматически запускаться через GitHub Actions.

## Как проходит проверка

```text
Источники
   │
   ▼
Загрузка подписок
   │
   ▼
Разбор конфигураций
   │
   ▼
Удаление дубликатов
   │
   ▼
Проверка IP через Cheburcheck
   │
   ▼
Проверка соединения через Xray
   │
   ▼
generate_204 / TCP / no
   │
   ▼
EXIT IP + страна
   │
   ▼
working.txt / top10.txt / all.txt
```

### Cheburcheck

IP серверов проходят техническую проверку через Cheburcheck. Для одинаковых IP используется кэш, чтобы не выполнять одну и ту же проверку несколько раз.

### Xray

Для проверки реального соединения проект создаёт временную локальную конфигурацию Xray и использует её для тестирования соответствующей конфигурации.

### Дополнительная проверка

Режим задаётся в `type.txt`:

```text
generate_204
```

HTTP-проверка через endpoint без содержимого.

```text
tcp
```

TCP-проверка заданной цели.

```text
no
```

Дополнительная проверка отключена.

При `generate_204` и `tcp` порядок прошедших конфигураций сохраняется. При `no` успешные конфигурации могут перемешиваться перед формированием результата.

## Результаты

В каталоге `proxies/` создаются:

| Файл | Назначение |
|---|---|
| `working.txt` | Основная подписка, максимум 100 конфигураций |
| `top10.txt` | TOP-10 отобранных конфигураций |
| `all.txt` | Все конфигурации, прошедшие полную проверку |
| `report.txt` | Статистика и информация об ошибках |
| `history.json` | История предыдущих проверок |

Результат проверки не является гарантией постоянной работоспособности: состояние серверов и сети может измениться после запуска.

## Настройка источников

В `subscriptions.txt` указывается по одному URL источника на строку:

```text
https://example.com/subscription-1
https://example.com/subscription-2
```

## Настройка режима

В `type.txt` указывается один из режимов:

```text
generate_204
```

```text
tcp
```

```text
no
```

Для обычной проверки рекомендуется `generate_204`.

## GitHub Actions

Workflow находится в:

```text
.github/workflows/check-proxies.yml
```

Он устанавливает Python и Xray, устанавливает зависимости, запускает проверку, при наличии Telegram-токена отправляет отчёт и сохраняет результаты.

Текущий запуск по расписанию — один раз в 24 часа, в 08:00 UTC:

```yaml
on:
  schedule:
    - cron: "0 8 * * *"
  workflow_dispatch: {}
```

Проверку также можно запустить вручную через GitHub Actions.

## Telegram

Для уведомлений используется `telegram_notify.py`.

ID чатов указываются в:

```text
telegram_chats.txt
```

по одному ID на строку.

Токен бота не хранится в репозитории. В GitHub Secrets создаётся:

```text
TELEGRAM_BOT_TOKEN
```

Telegram-отчёт показывает режим проверки, количество конфигураций, результат Cheburcheck, число рабочих конфигураций, протоколы, страны, ошибки и ссылки на подписки.

Статистика протоколов и стран относится к конфигурациям, попавшим в `working.txt`, чтобы отчёт соответствовал основной подписке.

## Установка

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd KnetaProxy
pip install -r requirements.txt
```

При локальном запуске должен быть установлен Xray:

```bash
xray version
```

После настройки `subscriptions.txt` и `type.txt`:

```bash
python checker.py
```

Результаты появятся в `proxies/`.

## Почему конфигурация может не попасть в результат

Конфигурация может быть исключена, если:

- она имеет неправильный формат;
- является дубликатом;
- не проходит проверку IP;
- Xray не может установить соединение;
- дополнительная проверка завершается ошибкой;
- невозможно определить необходимые сетевые данные;
- источник вернул некорректные или неполные данные.

Ошибки и статистика сохраняются в `proxies/report.txt`.

## Безопасность

Не храните в открытом репозитории:

- Telegram-токены;
- пароли;
- приватные ключи;
- другие секреты;
- персональные данные.

Токен Telegram-бота должен храниться в GitHub Secrets.
