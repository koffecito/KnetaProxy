Kneta собирает конфиги из ваших источников, проверяет их через Xray, отсеивает IP, заблокированные в РФ, и выкладывает готовые подписки. Работает на GitHub Actions по расписанию, при желании шлёт сводку в Telegram.

> [!WARNING]
> **Kneta не предоставляет VPN и не гарантирует безопасность чужих серверов.**
> - Проверка показывает лишь то, что сервер сейчас отвечает, но не то, что ему можно доверять.
> - Владелец стороннего сервера технически может видеть ваш трафик. Не передавайте через такие узлы пароли и важные данные.
> - Анонимность и защита данных не гарантируются.
> - Используйте только те источники и конфиги, которые вы вправе использовать. Ответственность за это лежит на вас.

## ⚡ Быстрый старт

1. Создайте секреты `SUBSCRIPTIONS` и `CACHE_SALT` (см. [Секреты](#-секреты)).
2. Откройте **Actions → Check proxies → Run workflow**.
3. Результат появится в папке [`sub/`](sub/). Дальше проверка идёт сама: **04:00 и 16:00 UTC**.

## 🔄 Как это работает

Kneta берёт много чужих конфигов и оставляет из них только те, которые реально работают и не заблокированы в РФ. Для этого каждый конфиг проходит несколько фильтров.

```text
Источники → Очистка → Живой ли? → Не заблокирован? → Сортировка → Подписки
```

**1. Сбор.** Kneta загружает ссылки из секрета `SUBSCRIPTIONS`, достаёт из них конфиги (`vless`, `vmess`, `trojan`, `hysteria2`, `hy2`) и убирает дубликаты и битые записи.

**2. Быстрая очистка.** Ещё до основной проверки отсеивается явный мусор:
- конфиги, у которых не находится IP-адрес;
- конфиги, чей IP уже известен как заблокированный (из кэша прошлых запусков);
- конфиги, у которых закрыт порт.

Это экономит время: на такие конфиги не тратится запуск Xray.

**3. Проверка: живой ли конфиг.** Для каждого оставшегося конфига запускается Xray и через него отправляется тестовый запрос. Если ответ пришёл, конфиг рабочий. Если нет или превышено время ожидания, он отбрасывается.

**4. Проверка: не заблокирован ли IP.** IP рабочих конфигов отправляются в Cheburcheck, который говорит, заблокирован ли адрес в РФ. Заблокированные отбрасываются. Если сервис ответил временной ошибкой (например, `429`), IP перепроверяется позже, а не отбрасывается сразу. Ответы запоминаются, поэтому один и тот же IP не проверяется заново при каждом запуске.

**5. Страна и сортировка.** Для каждого конфига определяется страна выходного IP. Конфиги сортируются: выше те, что дольше всего подряд оставались рабочими, так как они стабильнее.

**6. Результат.** Kneta собирает две подписки: основную (до 100 лучших конфигов) и полную (все рабочие). Если ни одного рабочего конфига не нашлось (например, все источники недоступны), прошлые подписки остаются как есть и не перезаписываются.

## 🔐 Секреты

Откройте **Settings → Secrets and variables → Actions → New repository secret** и создайте:

| Секрет | Нужен | Что указать |
|---|---|---|
| `SUBSCRIPTIONS` | Да | Ссылки на источники подписок, по одной на строку (можно и прямые конфиги) |
| `CACHE_SALT` | Рекомендуется | Любая случайная строка, например `k8Xp2mQ7vR4tZ9nB` |
| `TELEGRAM_BOT_TOKEN` | Для Telegram | Токен бота от BotFather |

Пример `SUBSCRIPTIONS` (адреса демонстрационные):

```text
https://example.com/subscription-one
https://example.com/subscription-two
```

> [!IMPORTANT]
> **`CACHE_SALT` задайте один раз и не меняйте.** Результаты проверок хранятся в `sub/history.json` в виде хэшей, и ключом для них служит эта строка. Пока она не меняется, смена источников не сбрасывает кэш, и запуски остаются быстрыми. Если строку изменить или удалить, кэш потеряется, и следующий запуск будет долгим.

> [!CAUTION]
> Не публикуйте реальные источники, конфиги и токены в README, issues, коммитах и скриншотах.

## ⚙️ Настройка проверки

В `other/type.txt` укажите один режим:

| Режим | Что делает |
|---|---|
| `generate_204` | HTTP-запрос через конфиг. Рекомендуется |
| `tcp` | Только TCP-соединение |
| `no` | Без дополнительной проверки |

В режиме `generate_204` достаточно, чтобы ответил любой из адресов (по умолчанию `gstatic.com` и `cp.cloudflare.com`). Ответ `429` тоже считается успехом. Если выходной IP или страну определить не удалось, конфиг попадает в полную подписку со страной «Неизвестно».

Как Kneta не упирается в лимиты `429`: интервал между запросами к Cheburcheck сам растёт при ошибках и возвращается обратно; ответы по IP кэшируются на 48 часов, страны на 14 дней.

<details>
<summary><b>🎛 Тонкая настройка</b></summary>

<br>

Необязательные переменные, задаются в блоке `env` шага **Run checker** в `.github/workflows/check-proxies.yml`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MAX_WORKERS` | 32 | Сколько конфигов проверяется одновременно |
| `MAX_PROXIES` | 100 | Размер основной подписки |
| `REQUEST_TIMEOUT` | 5 | Таймаут запроса `generate_204`, сек |
| `GENERATE_204_URLS` | gstatic, cloudflare | Адреса проверки, через запятую |
| `CHEBURCHECK_CACHE_HOURS` | 48 | Срок хранения вердикта по IP, часы |
| `CHEBURCHECK_MAX_INTERVAL` | 10 | Максимальный интервал между запросами при 429, сек |

Названия подписок, интервал обновления и анонс задаются в `other/info.txt`.

</details>

## ▶️ Запуск

- **Автоматически:** 04:00 и 16:00 UTC.
- **Вручную:** **Actions → Check proxies → Run workflow**. В поле `xray_version` можно указать другую версию Xray-core, пустое поле берёт версию из workflow.
- Одновременно идёт только один запуск, лимит времени 40 минут.

> [!NOTE]
> Первый запуск на пустом кэше (или после смены `CACHE_SALT`) идёт заметно дольше: все IP проверяются заново. Дальше будет быстрее.

<details>
<summary><b>📨 Telegram-уведомления (необязательно)</b></summary>

<br>

Без этого всё работает, просто сообщения не приходят.

**1. Бот.** В Telegram откройте **@BotFather**, отправьте `/newbot`, задайте имя и username (на `bot` в конце). Токен добавьте в секрет `TELEGRAM_BOT_TOKEN`.

> [!CAUTION]
> Токен даёт полный контроль над ботом. Если он утёк, перевыпустите его в BotFather и обновите секрет.

**2. Чат.** Личный чат: откройте бота и нажмите **Start**. Группа или канал: добавьте бота и дайте право писать.

**3. ID чата.** Напишите боту, откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (подставив токен, ссылку не публикуйте) и найдите `message → chat → id`. У групп ID обычно начинается с `-100`. Пустой ответ значит, что боту нужно написать ещё раз.

**4. Файл.** Впишите ID в `telegram/telegram_chats.txt`, по одному на строку:

```text
123456789
-1001234567890
```

Токен в файл вписывать нельзя, только ID.

</details>

```bash
pip install -r other/requirements.txt
python other/validate.py
python checker.py

```

Перед запуском задайте переменные окружения `SUBSCRIPTIONS` (и при желании `CACHE_SALT`, `TELEGRAM_BOT_TOKEN`). Не записывайте реальные источники в файлы, которые попадут в Git.

</details>

<details>
<summary><b>🛠 Если что-то не работает</b></summary>

<br>

| Проблема | Что делать |
|---|---|
| `SUBSCRIPTIONS` не найден | Проверьте точное имя секрета и что он создан в нужном репозитории |
| Запуск стал долгим | Проверьте, не менялся ли `CACHE_SALT`; в `report.txt` смотрите «Cheburcheck запросов» |
| Много ответов 429 | Нормально на пустом кэше, дальше станет меньше |
| Сообщение в Telegram не приходит | Проверьте токен и что в личном чате нажат **Start** |
| `chat not found` | Неверный ID или у бота нет доступа к чату |
| `bot was blocked by the user` | Откройте чат с ботом и нажмите **Start** |
| Конфига нет в результате | Он мог быть дубликатом, иметь неверный формат или не пройти проверку |

</details>

## 🛡 Безопасность и ответственность

- Не храните токены, пароли и приватные конфиги в открытых файлах репозитория.
- Удаление секрета из настроек не стирает его из старой истории Git и логов. При утечке перевыпускайте токен.
- Проверка доступности не подтверждает безопасность, надёжность или законность использования чужого сервиса.
- Kneta не предоставляет собственную VPN-инфраструктуру и не гарантирует анонимность. Документация не является юридической консультацией.
